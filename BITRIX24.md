# Битрикс24: проверенная схема и границы демо

Документация проверена 11 ноября 2026. Реальный портал компании не предоставлен, поэтому его тариф, права, заполненность полей и кадровый процесс не проверялись. В этом приложении нет секретов, внешних API-вызовов или работающего обработчика вебхуков.

## Вариант 1: профиль сотрудника

[`ONUSERADD`](https://apidocs.bitrix24.ru/api-reference/common/events/on-user-add.html) приходит после первого входа сотрудника и завершения регистрации, а не сразу после приглашения. На событие можно подписаться исходящим вебхуком или приложением. Исходящий вебхук не передаёт OAuth-токены.

[`user.add`](https://apidocs.bitrix24.ru/api-reference/user/user-add.html) приглашает пользователя в Битрикс24 и требует EMAIL; это не событие мгновенного создания полностью зарегистрированного профиля. Наша форма с тремя полями этот метод не вызывает: она демонстрирует обработку данных уже доступного сотрудника.

При заполненных значениях и достаточных правах можно использовать:

| Поле | Применение |
| --- | --- |
| `ID` | Связь с профилем; в будущей интеграции — ключ для защиты от дублей вместе с идентификатором портала |
| `NAME`, `LAST_NAME` | Имя и фамилия |
| `WORK_POSITION` | Название должности |
| `UF_DEPARTMENT` | ID подразделений; названия требуют справочника структуры |
| `UF_EMPLOYMENT_DATE` | Дата приёма, если заполнена |
| `EMAIL` | Контакт, если заполнен |

Набор полей зависит от скоупа и прав. [`user.get`](https://apidocs.bitrix24.ru/api-reference/user/user-get.html) позволяет получить доступные данные профиля по фильтру. Недостающие значения должен уточнять HR. В демонстрации подразделение и наставник назначаются по выбранной роли, дата — текущий день, ID — локальное вымышленное число; эти значения не выдаются за полученные из API.

## Вариант 2: задача приёма

Компания уже использует задачи для приёма и увольнения, поэтому возможен запуск через [`ONTASKADD`](https://apidocs.bitrix24.ru/api-reference/tasks/events-tasks/on-task-add.html). Событие передаёт ID задачи; данные читаются через [`tasks.task.get`](https://apidocs.bitrix24.ru/api-reference/tasks/tasks-task-get.html) в пределах прав.

Необходима настройка того, какие задачи являются кадровыми: например, выделенный процесс и заранее согласованные поля. Произвольный заголовок задачи не разбирается и не считается основанием автоматически создавать сотрудника. Нужны структурированные поля или ссылка на профиль, а также правило сопоставления должности и наставника. Если сведения становятся известны позднее, можно рассмотреть [`ONTASKUPDATE`](https://apidocs.bitrix24.ru/api-reference/tasks/events-tasks/on-task-update.html) и обработку выбранного состояния процесса.

## Что назначает «В команде»

Учебная база, конкретный маршрут и наставник — правила нашего приложения. Стандартное поле «наставник» в этой схеме не заявляется: нужен собственный справочник или согласованное пользовательское поле. Должность сопоставляется с маршрутом по конфигурации; неизвестное название направляется HR на ручное решение.

Для рабочего подключения нужны серверный обработчик с проверкой подлинности события, безопасное хранение авторизации, защита от повторных событий, проверка прав и полей, реальное приглашение в учебный кабинет, общая база и управление доступом. Это следующий этап, не скрытая функциональность демо.
